Data Hub match, merge & survivorship

Repository Boomi-Bank, model customermaster, sources CORE_BANKING SALESFORCE_FSC AML_KYC RM_ROSTER. Records match on customerId or idDocumentHash; each field then takes the value from the system that owns it.

3

AUD normalisation of positions

From the consolidated_positions data product (BB_P3_Consolidated_Positions_API, live). Every deposit, loan and card is converted to AUD at the treasury mid-rate, rounded half-up to 2 dp; loans carry interest accrued to today and an indicative payout.

4

Live data product calls

Each button calls the local facade, which proxies to the Boomi Web Services endpoint with credentials held server-side. If Boomi is unreachable or answers with its own error (Data Hub credentials pending), it falls back to the mock implementation of the same contract; the response says which served it and why.

Shared subprocess

[SUB] BB Account & Loan Source Extract

One extract, one set of banking rules (interest, payout, DQ flags) reused by P3, P4 and P6, so the assistant, the alerts and the payout always agree.

Act 1 · onboarding

BB_P5_Digital_Onboarding_Orchestration

Resolves in Data Hub, verifies ID, screens (Try/Catch), scores risk + bundle, fans out to 7 systems incl. a live Data Hub upsert.

Act 3a · payout

BB_P6_Loan_Payout_Closure_Orchestration

Compliance hold, payout via the shared extract, fixes the DQ flags before money moves, 9-way fan-out.

Act 3b · security release

BB_P7_Security_Release_Status

Route on LODGED / SETTLED / RELEASED; RELEASED returns the offset account to everyday use.

Agent guardrails on top of all three: the Boomi Banking Assistant never reveals ID document numbers or hashes, the TFN, or full card and account numbers; fee or break-cost waivers over AUD 200 need supervisor approval; personal financial advice is a denied topic (general information only).
