ElectroMart Order-to-Cash — Reference Demo

A self-service web portal where customers look up an order, view items and status, and request a new delivery date — all backed by a Boomi iPaaS integration that simulates a real Order-to-Cash flow with a mock ERP/SAP sync. พอร์ทัลแบบบริการตนเองสำหรับลูกค้าค้นหาคำสั่งซื้อ ดูสินค้าและสถานะ และขอวันส่งใหม่ — ทั้งหมดขับเคลื่อนโดย Boomi iPaaS ที่จำลองกระบวนการ Order-to-Cash จริงพร้อมการซิงค์ ERP/SAP จำลอง Isang self-service na web portal kung saan tinitingnan ng customer ang order, items, at status, at nakapag-request ng bagong delivery date — sinusuportahan ng Boomi iPaaS integration na nagmo-mock ng totoong Order-to-Cash flow kasama ang mock ERP/SAP sync. Portal web swalayan tempat pelanggan mencari pesanan, melihat item dan status, serta meminta tanggal pengiriman baru — semuanya didukung oleh integrasi Boomi iPaaS yang menyimulasikan alur Order-to-Cash nyata dengan sinkronisasi ERP/SAP tiruan.

What this demo includes

  • Public-facing portal — responsive HTML/CSS/JS single-page app with light & dark themes and an in-page calendar picker.
  • Two REST endpoints exposed by Boomi Web Services Server: lookup & update.
  • Five realistic electronics orders (iPhone, Dell XPS, Galaxy S24, Sony headphones, LG OLED) covering every stage of the O2C pipeline.
  • Mock ERP/SAP sync with a confirmation number and timestamped acknowledgement.
  • Postman collection for API exercise.

สิ่งที่รวมอยู่ในเดโม

  • พอร์ทัลสาธารณะ — เว็บแอปแบบ Single Page (HTML/CSS/JS) ตอบสนองได้ ทั้งโหมดสว่างและมืด พร้อมตัวเลือกวันที่แบบปฏิทินในหน้าเดียวกัน
  • REST endpoint สองรายการ ที่เปิดผ่าน Boomi Web Services Server: ค้นหาและอัปเดต
  • คำสั่งซื้อสินค้าอิเล็กทรอนิกส์ตัวอย่าง 5 รายการ (iPhone, Dell XPS, Galaxy S24, หูฟัง Sony, LG OLED) ครอบคลุมทุกขั้นตอนของไปป์ไลน์ O2C
  • การซิงค์ ERP/SAP จำลอง พร้อมหมายเลขยืนยันและการตอบรับมีตราเวลา
  • คอลเลกชัน Postman สำหรับทดสอบ API

Ano ang nasa demo na ito

  • Dalawang REST endpoint na inilalantad ng Boomi Web Services Server: lookup at update.
  • Limang totoong-buhay na electronics order (iPhone, Dell XPS, Galaxy S24, Sony headphones, LG OLED) na sumasaklaw sa lahat ng yugto ng O2C pipeline.

Architecture

Three layers: a static portal in the customer's browser, two Boomi WSS-hosted REST endpoints, and a mocked ERP/SAP backend. Boomi orchestrates lookup and update, applies business rules, and returns JSON. มีสามชั้น: พอร์ทัลแบบสแตติกในเบราว์เซอร์ลูกค้า, REST endpoint สองตัวที่โฮสต์โดย Boomi WSS, และระบบ ERP/SAP จำลอง Boomi เป็นตัวควบคุมการค้นหาและการอัปเดต ใช้กฎทางธุรกิจ และตอบกลับเป็น JSON Tatlong layer: static portal sa browser ng customer, dalawang REST endpoint na hino-host ng Boomi WSS, at isang mock ERP/SAP backend. Ang Boomi ang nag-o-orchestrate ng lookup at update, nag-aapply ng business rules, at nagbabalik ng JSON. Tiga lapisan: portal statis di browser pelanggan, dua endpoint REST yang di-host oleh Boomi WSS, dan backend ERP/SAP tiruan. Boomi mengatur pencarian dan pembaruan, menerapkan aturan bisnis, dan mengembalikan JSON.

The Order-to-Cash flow

A retail order moves through five stages from confirmation to delivered. Reschedule is allowed only while the order is at CONFIRMED, PROCESSING, or PICKED_PACKED — once it ships, the carrier owns the route. คำสั่งซื้อเดินทางผ่าน 5 ขั้นจากการยืนยันถึงการส่งมอบ การเปลี่ยนวันส่งทำได้เฉพาะระยะ CONFIRMED, PROCESSING หรือ PICKED_PACKED เท่านั้น — หลังจากจัดส่งแล้ว เส้นทางจะอยู่กับผู้ขนส่ง Dumadaan ang isang retail order sa limang yugto mula confirmation hanggang delivered. Pinapayagan ang reschedule lamang habang ang order ay CONFIRMED, PROCESSING, o PICKED_PACKED — kapag naipadala na, hawak na ng carrier ang ruta. Pesanan retail melewati lima tahap dari konfirmasi hingga terkirim. Penjadwalan ulang hanya diizinkan saat status CONFIRMED, PROCESSING, atau PICKED_PACKED — setelah dikirim, rute sudah dipegang oleh kurir.

Figure 2 — O2C pipeline with reschedule eligibility windows.

A real retailer would also run inventory checks, fraud screening, payment capture, and carrier handoff at the boundaries. Those are extension points — see Extensions. ผู้ค้าปลีกจริงจะตรวจสอบสต็อก ป้องกันการฉ้อโกง รับชำระเงิน และส่งต่อให้ผู้ขนส่งที่ขอบเขตเหล่านี้ ทุกอย่างเป็นจุดขยาย — ดู ส่วนขยาย Ang totoong retailer ay magpapatakbo rin ng inventory check, fraud screening, payment capture, at carrier handoff sa mga boundary. Mga extension point yun — tingnan ang Extensions. Pengecer sungguhan juga akan menjalankan pemeriksaan stok, deteksi penipuan, penangkapan pembayaran, dan serah-terima kurir pada batas-batas ini. Itu titik perluasan — lihat Ekstensi.

Boomi Process — Order Lookup

type: process listener: WSS 10 shapes allowSimultaneous=true

A Web Services Server listener accepts a JSON body {"orderId":"…"}, captures the ID into a Dynamic Document Property, then a Route step branches on the value to one of five known orders or a default 404 response. Each branch builds the order JSON via a Message shape, then converges at a single Return Documents shape that emits the response. Listener Web Services Server รับ JSON body {"orderId":"…"} เก็บ ID ลงใน Dynamic Document Property จากนั้น Route step แยกตามค่าไปยังคำสั่งซื้อที่รู้จัก 5 รายการ หรือเส้นทาง default 404 แต่ละสาขาสร้าง JSON ผ่าน Message shape แล้วมารวมที่ Return Documents เพื่อส่งคำตอบ Tinatanggap ng Web Services Server listener ang JSON body {"orderId":"…"}, kinukuha ang ID sa isang Dynamic Document Property, tapos ang Route step ay sumasanga ayon sa value patungo sa isa sa limang kilalang order o sa default 404. Bawat sangay ay nagbu-build ng order JSON gamit ang Message shape, tapos nagtatagpo sa isang Return Documents shape para ipadala ang response. Pendengar Web Services Server menerima body JSON {"orderId":"…"}, menangkap ID ke Dynamic Document Property, lalu Route step bercabang berdasarkan nilai ke salah satu dari lima pesanan dikenal atau respons default 404. Setiap cabang membangun JSON pesanan melalui Message shape, lalu bertemu di satu Return Documents shape yang memancarkan respons.

Boomi Process — Order Update

type: process listener: WSS 5 shapes mock SAP sync

A linear pipeline. The WSS listener receives the JSON body, Set Properties extracts orderId and newDeliveryDate from the request profile and synthesises a confirmation number plus an updatedAt ISO timestamp. A Notify step writes a structured log entry. A Message step composes the response JSON and Return Documents emits it. ไปป์ไลน์เชิงเส้น Listener WSS รับ JSON body, Set Properties ดึง orderId และ newDeliveryDate จาก request profile และสร้างหมายเลขยืนยันพร้อม updatedAt ISO timestamp ขั้น Notify เขียนล็อกแบบมีโครงสร้าง ขั้น Message ประกอบ JSON ตอบกลับ และ Return Documents ส่งออก Linear na pipeline. Tinatanggap ng WSS listener ang JSON body, ang Set Properties ay kumukuha ng orderId at newDeliveryDate mula sa request profile at gumagawa ng confirmation number at updatedAt ISO timestamp. Ang Notify step ay nagsusulat ng structured log entry. Bumubuo ng response JSON ang Message step at ipinapadala ito ng Return Documents. Pipa linier. Pendengar WSS menerima body JSON, Set Properties mengekstrak orderId dan newDeliveryDate dari profil permintaan dan menyintesis nomor konfirmasi serta tanda waktu ISO updatedAt. Langkah Notify menulis entri log terstruktur. Langkah Message menyusun JSON respons dan Return Documents memancarkannya.

Confirmation number formula

Built deterministically by Set Properties as "RSC-" + DDP_ORDER_ID + "-" + currentDate("yyyyMMddHHmmss"). Real systems would generate a UUID or a sequence from the ERP — this format is human-friendly and traceable for the demo. สร้างอย่างเป็นระบบโดย Set Properties: "RSC-" + DDP_ORDER_ID + "-" + currentDate("yyyyMMddHHmmss") ระบบจริงจะใช้ UUID หรือลำดับจาก ERP รูปแบบนี้อ่านง่ายและตรวจสอบได้สำหรับเดโม Ginawa nang deterministic ng Set Properties bilang "RSC-" + DDP_ORDER_ID + "-" + currentDate("yyyyMMddHHmmss"). Sa totoong sistema, gagawa ng UUID o sequence mula sa ERP — friendly at traceable ang format na ito para sa demo. Dibangun secara deterministik oleh Set Properties sebagai "RSC-" + DDP_ORDER_ID + "-" + currentDate("yyyyMMddHHmmss"). Sistem nyata akan menghasilkan UUID atau urutan dari ERP — format ini ramah pengguna dan dapat dilacak untuk demo.

Extensions & SAP integration

The Boomi platform ships connectors for production-grade retail backends. Common upgrades from this demo: Boomi platform มี connector สำหรับ retail backend ระดับโปรดักชัน การยกระดับทั่วไปจากเดโมนี้: May mga connector ang Boomi platform para sa production-grade na retail backend. Mga karaniwang upgrade mula sa demo na ito: Platform Boomi menyediakan konektor untuk backend retail kelas produksi. Peningkatan umum dari demo ini:

  • Boomi for SAP — replace the Message-step "mock SAP" with a real SAP connector call to SalesOrder/DeliveryDocument BAPIs or RFCs. Map our JSON to VBAK/VBAP structures. Boomi for SAP — เปลี่ยน Message step "mock SAP" เป็นการเรียก SAP connector จริงไปยัง SalesOrder/DeliveryDocument BAPI หรือ RFC แมป JSON ของเราไปยัง VBAK/VBAP Boomi for SAP — palitan ang Message-step na "mock SAP" ng tunay na SAP connector call patungo sa SalesOrder/DeliveryDocument BAPIs o RFCs. I-map ang JSON natin sa VBAK/VBAP structures. Boomi for SAP — ganti langkah Message "mock SAP" dengan panggilan konektor SAP nyata ke BAPI/RFC SalesOrder/DeliveryDocument. Petakan JSON kami ke struktur VBAK/VBAP.

Boomi DataHub — ส่งเสริมข้อมูลลูกค้าและคำสั่งซื้อเป็นข้อมูลแม่บท เพื่อให้ Salesforce, SAP และระบบขนส่งสอดคล้องกัน Boomi DataHub — i-promote ang customer + order bilang master records para magkapareho ang Salesforce, SAP, at carrier system. Boomi DataHub — promosikan pelanggan + pesanan ke record master agar Salesforce, SAP, dan sistem kurir tetap selaras.
