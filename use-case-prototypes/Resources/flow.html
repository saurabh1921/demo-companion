Data Hub match, merge & survivorship

Model equipmentmaster, sources SAP_PM FLEET_MGMT OEM_TELEMATICS SERVICENOW CREW_ROSTER. Records match on any of sapEquipmentNo, fleetId, oemSerial or cmdbCi once cleansed; each field then takes the value from the system that owns it.

CMDB and Data Hub, each doing its own job. The ServiceNow CMDB stays the system of record for onboard technology (onboard computer, telematics gateway, collision avoidance, firmware) and for the CI relationships incident and change depend on: the onboardTech row above is ServiceNow's value, untouched. Data Hub is the referee that keeps every system agreeing on which machine it is, and it syncs both ways: stage 4 sends the golden IDs back so the CIs carry the SAP number and the clean fleet ID.
3

Unit normalisation

From the production_availability data product (BR_P3_Production_Availability_API, live) and the breakdown triage. The Komatsu truck reports payload in short tons and its feed reports fuel in US gallons; Cat telematics reports temperature in Fahrenheit. Site standard: tonnes, litres, Celsius.

4

Sync golden IDs back

The outbound half of the master-data loop: BR_P8_Golden_Record_Sync reads every golden record live from Data Hub, compares it with what ServiceNow, SAP PM and dispatch hold today, and sends each system only what it is missing.

Inbound (BR_P1): SAP, dispatch, telematics, ServiceNow and the roster feed Data Hub, which matches and merges them.
⇄
Outbound (BR_P8): ServiceNow CIs get u_sap_equipment + u_fleet_id, SAP gets TIDNR + ZZ_CMDB_CI, dispatch gets SAP_EQUIPMENT + CMDB_CI.
POST /api/v1/mine/golden-sync → /ws/simple/createBrgoldensync

Press the button to run the sync.

Live data product calls

Each button calls the local facade, which proxies to the Boomi Web Services endpoint with credentials held server-side. If Boomi is unreachable or answers with its own error, it falls back to the mock implementation of the same contract; the response says which served it and why.
