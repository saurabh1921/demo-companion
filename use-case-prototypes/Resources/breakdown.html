Act 3 · Breakdown to repair, orchestrated by Boomi

The alarm only knows a serial number. Boomi knows the truck.

07:42. Cat VisionLink raises a high coolant temperature alarm for serial CAT0793FKL1234, in Fahrenheit. Boomi resolves the serial to all four IDs in Data Hub, fixes the data first (converts the reading, links the operator's existing ServiceNow incident instead of opening a duplicate, extends the open SAP work order), reserves parts, costs the downtime in tonnes and dollars, then tells eight systems. Repair events from the maintainer's tablet then bring the truck back: in repair, tested, released.

What is real here

    
Send alarm to Boomi calls the deployed process BR_P6_Breakdown_Response_Orchestration through
      /ws/simple/createBrbreakdown. Resolving the serial is a live Data Hub query on
      equipmentmaster, and marking the truck DOWN is a live Data Hub upsert.
      Triage runs on the shared [SUB] BR Operations Extract, the same subprocess the data products use. Every repair
      button posts a live event to BR_P7_Return_To_Service (/ws/simple/updateBrrepairstatus),
      whose Route step fires one path per status; RELEASED writes the truck back to STANDBY in Data Hub. ServiceNow,
      SAP PM, inventory, dispatch, the crew roster, short-interval control and messaging are stub sends shaped like each system's API.
      Offline, or as a file, the page replays traces recorded from the live processes.
