1The business problem

ปัญหาทางธุรกิจ

EnglishHospitals send claims to BVTPA in whatever format their own systems produce. Today that variety is absorbed by people: staff re-key data, chase missing pre-authorisation codes, and check policy status by hand. The cost is slow settlement, inconsistent decisions, and no reliable view of why a claim was held back.

ภาษาไทยโรงพยาบาลแต่ละแห่งส่งข้อมูลเคลมมายัง BVTPA ในรูปแบบที่ระบบของตนเองสร้างขึ้น ปัจจุบันความหลากหลายนี้ถูกจัดการด้วยคน เจ้าหน้าที่ต้องคีย์ข้อมูลซ้ำ ติดตามรหัสอนุมัติล่วงหน้าที่ขาดหาย และตรวจสอบสถานะกรมธรรม์ด้วยมือ ผลที่ตามมาคือการจ่ายเงินล่าช้า การตัดสินใจไม่สม่ำเสมอ และไม่มีภาพที่ชัดเจนว่าเหตุใดเคลมจึงถูกพักไว้

2What was built

สิ่งที่สร้างขึ้น

EnglishA single Boomi integration that accepts three different hospital claim formats, converts every claim into one standard record, applies BVTPA’s adjudication rules automatically, and routes each claim to one of three outcomes — always with a reason attached. It runs end to end in under five seconds.

ภาษาไทยระบบเชื่อมต่อบน Boomi หนึ่งชุด ที่รับข้อมูลเคลมจากโรงพยาบาลสามรูปแบบที่ต่างกัน แปลงทุกเคลมให้เป็นโครงสร้างมาตรฐานเดียว ใช้กฎการพิจารณาของ BVTPA โดยอัตโนมัติ และส่งเคลมแต่ละรายการไปยังหนึ่งในสามผลลัพธ์ พร้อมระบุเหตุผลกำกับเสมอ ทำงานครบวงจรภายในเวลาไม่ถึงห้าวินาที

OutcomeEnglishภาษาไทย
1Direct billing settlement — BVTPA pays the hospital, the member pays nothingเรียกเก็บเงินโดยตรง — BVTPA จ่ายให้โรงพยาบาล สมาชิกไม่ต้องสำรองจ่าย
2Member reimbursement — the member paid, BVTPA repays themเบิกคืนเงินสมาชิก — สมาชิกสำรองจ่ายไปก่อน แล้ว BVTPA จ่ายคืน
3Manual adjudicator queue — a person reviews it, with the reason code shownคิวพิจารณาโดยเจ้าหน้าที่ — เจ้าหน้าที่ตรวจสอบ พร้อมแสดงรหัสเหตุผล

3Why it matters to BVTPA

คุณค่าต่อ BVTPA
#Englishภาษาไทย
1Onboard a new hospital without changing the rules. Only a new source profile and map are added; the adjudication logic is untouched.เพิ่มโรงพยาบาลใหม่ได้โดยไม่ต้องแก้กฎ เพิ่มเพียงโปรไฟล์ข้อมูลและการแปลงข้อมูลใหม่ ตรรกะการพิจารณาไม่ถูกแตะต้อง
2Consistent decisions. The same rules run in the same order on every claim, every time.การตัดสินใจสม่ำเสมอ ใช้กฎชุดเดียวกันในลำดับเดียวกันกับทุกเคลม ทุกครั้ง
3Nothing is silently rejected. Every held claim reaches a human with a reason code.ไม่มีเคลมใดถูกปฏิเสธเงียบ ๆ ทุกเคลมที่ติดเงื่อนไขจะถึงมือเจ้าหน้าที่พร้อมรหัสเหตุผล
4Business owns the reference data. Eligibility, network status and contracts are maintained by BVTPA staff in the Boomi UI — no developer, no release.ฝ่ายธุรกิจเป็นเจ้าของข้อมูลอ้างอิง สิทธิ์สมาชิก สถานะเครือข่าย และสัญญา แก้ไขได้เองในหน้าจอ Boomi ไม่ต้องใช้นักพัฒนาและไม่ต้องรอรอบปล่อยระบบ
5Auditable. Every step, every document and every decision is logged per run.ตรวจสอบย้อนหลังได้ ทุกขั้นตอน ทุกเอกสาร และทุกการตัดสินใจถูกบันทึกไว้ในแต่ละรอบการทำงาน

4The rules, in order

กฎการพิจารณาตามลำดับ

First match wins. ตรวจตามลำดับ เจอเงื่อนไขใดก่อนใช้เงื่อนไขนั้น

#CheckการตรวจสอบOutcome / ผลลัพธ์
1Look up the policy in BVTPA’s member recordsค้นหากรมธรรม์ในฐานข้อมูลสมาชิกของ BVTPA—
2Policy not foundไม่พบกรมธรรม์POLICY_NOT_FOUND
3Policy not activeกรมธรรม์ไม่มีผลบังคับPOLICY_INACTIVE
4–5Panelled hospital and a direct billing contract with that insurerโรงพยาบาลอยู่ในเครือ และ มีสัญญาเรียกเก็บเงินโดยตรงกับบริษัทประกันนั้นCashless route, otherwise reimbursement เส้นทางไม่สำรองจ่าย มิฉะนั้นเบิกคืนเงิน
6Claim amount exceeds the remaining benefit limitยอดเคลมเกินวงเงินคงเหลือEXCEED_LIMIT
7–8Cashless route, pre-authorisation required, no code suppliedเส้นทางไม่สำรองจ่าย ต้องขออนุมัติล่วงหน้า แต่ไม่มีรหัสMISSING_PREAUTH
9Otherwise approveหากผ่านทั้งหมด อนุมัติAPPROVED_CASHLESS APPROVED_REIMBURSEMENT

7Scope boundaries — read before demonstrating

ขอบเขต: โปรดอ่านก่อนนำไปสาธิต
Englishภาษาไทย
All hospitals, insurers, policy numbers and claim amounts are invented for demonstration. No real patient or provider data is used.โรงพยาบาล บริษัทประกัน เลขกรมธรรม์ และยอดเคลมทั้งหมดถูกสมมติขึ้นเพื่อการสาธิต ไม่มีการใช้ข้อมูลผู้ป่วยหรือสถานพยาบาลจริง
Claim data is generated inside the process itself, not received from any hospital system.ข้อมูลเคลมถูกสร้างขึ้นภายในกระบวนการเอง ไม่ได้รับมาจากระบบของโรงพยาบาลใด
Outputs are written to the execution log, not sent to a payment or claims system.ผลลัพธ์ถูกบันทึกลงในล็อกการทำงาน ไม่ได้ส่งต่อไปยังระบบจ่ายเงินหรือระบบเคลมจริง
The runtime used is a Boomi training cloud, not a production runtime.ระบบทำงานอยู่บนคลาวด์สำหรับการฝึกอบรมของ Boomi ไม่ใช่ระบบจริง

8Path to production

แนวทางสู่การใช้งานจริง
#Englishภาษาไทย
1Replace the three generated feeds with real intake — SFTP, portal upload or API per hospitalแทนที่ข้อมูลจำลองสามชุดด้วยช่องทางรับจริง เช่น SFTP อัปโหลดผ่านพอร์ทัล หรือ API ของแต่ละโรงพยาบาล
2Point the eligibility lookup at BVTPA’s live policy system instead of the demo tableเชื่อมการตรวจสอบสิทธิ์ไปยังระบบกรมธรรม์จริงของ BVTPA แทนตารางสาธิต
3Deliver the three outputs to the settlement, reimbursement and workqueue systemsส่งผลลัพธ์ทั้งสามไปยังระบบจ่ายเงิน ระบบเบิกคืน และระบบคิวงานจริง
4Add error handling, alerting and reprocessing for failed batchesเพิ่มการจัดการข้อผิดพลาด การแจ้งเตือน และการประมวลผลซ้ำสำหรับชุดข้อมูลที่ล้มเหลว
5Move to a production runtime with environment-specific credentials and access controlย้ายไปยังระบบรันจริง พร้อมข้อมูลรับรองและการควบคุมสิทธิ์ตามสภาพแวดล้อม
6Agree volume, latency and availability targets before go-liveตกลงเป้าหมายด้านปริมาณงาน ความเร็ว และความพร้อมใช้งาน ก่อนเปิดใช้จริง
