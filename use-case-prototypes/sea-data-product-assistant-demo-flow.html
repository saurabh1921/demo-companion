1

What a data product actually is

Land the concept before anything technical. No Boomi yet.

4 min/why
Say first
“A data product isn't a pipeline and it isn't a table. It's a contract: an agreed definition, a known grain, one unit of measure, an owner, and a governed way to consume it. Most analytics programmes stall because they build the pipeline before anyone agrees what a ‘subsidiary’ is.”
Do
Open /why. Let them read the two numbers before you speak.
They see
$6,325,649 against $8,593,524 — a 26.4% gap on the same month, from the same two systems, with nobody having made a mistake.
Say
“Vietnam's currency is recorded as VDN in one system. There's no such currency. The conversion finds no rate, skips the row, and the report still runs. You don't get an error — you get a regional total that's quietly a quarter short.”
Close act
“That's the problem a data product solves. Not ‘we need better dashboards’ — we need one definition everyone draws from.”

Scroll the three causes if there's time; the Vietnam one alone is enough.

The row that pre-empts the pricing objection

Two products are published. subsidiary_performance_consolidated needs Data Hub because two ERPs disagree about the same entity. open_receivables_by_subsidiary needs none, because a single system owns the receivable. Say this before anyone asks whether they have to buy the whole stack: you need master data when your sources conflict, not because you want a data product.

Do
Open /catalog. Go straight to Ownership, then the Source of truth column in the contract table.
Say
“This is what makes it a product rather than a job someone runs. There's a person accountable for what the numbers mean, a team accountable for delivery, and a named steward per field. Finance owns currency. Operations owns trading status. Those aren't settings — they're decisions, with names against them.”
Then
Scroll to Known limitations. Don't skip it.
Say
“A product that hides its limitations burns its consumers once. Publishing them is what lets someone design around a gap instead of discovering it in UAT.”

How Companion compresses the build

The meta-story. Every artifact was authored conversationally against the live APIs.

5 minterminal
2m 01sData Hub model published → deployed → both ERPs loaded → 4 reconciled golden records
11sAgent tool authored → installed → ACTIVE
10sAgent defined → packaged → deployed to Agent Garden
~1 hrEmpty folder → exec chat window, including a 25-minute network block
Say
“None of this was clicked together. It was described in English, and Companion wrote the model XML, the match rules, the source ranking, the process canvas, the agent definition and the tool — then deployed and tested each one against the live platform.”
The point
Not that it is fast. That the slow part moved. Design decisions — who owns currency, what the grain is, what the contract exposes — took the time. Construction stopped being the constraint.
Show
Scroll back through this session's terminal so they see plain-English instructions producing deployed platform artifacts.
Optional — the strongest beat if you're confident

Take a request from the room and build it live. A safe one: “add the FX rate and its as-at date to the API response” — a real gap published in the catalogue, and a small change to one Groovy step, push, deploy, re-call. Have a fallback ready; a live build that stalls costs more than it wins.

5

The working prototype

Close on the payoff. This is the part they'll remember.

6 min/flow then chat
Do
Open /flow with Indonesia selected. Check the chip top-right reads hub: live. Walk stages 1→3 quickly.
Say
“Stage two is reading Data Hub right now — this isn't a screenshot. Currency went to SAP, status went to Oracle, and you can see which value won.”
Then
Stage 4 — press Call without credentials, get 401. Then Call the product.
Then
Stage 5 — click Thailand. Wait. Say nothing.
They see
The agent volunteers, unprompted, that Thailand is Dormant and that its figures carry that caveat.
Say
“Nobody asked about status. That word came from a survivorship rule set in Data Hub — Oracle outranks SAP on trading status, so ‘Dormant’ beat ‘Inactive’. A governance decision made by the data owners just changed what an executive was told. That is the whole argument for doing this in the right order.”
Governed lookup
Ask “Who is the entity owner for Vietnam, and who do I contact in finance?”
They see
Entity owner Nguyen Thi Lan, finance contact vn.finance@example.com — and the agent says it comes from the governed master record.
Say
“Those two answers came from two different systems. Operations is authoritative for who runs the entity, because the finance system’s copy goes stale when people move. Finance is authoritative for the contact mailbox. One record, one query, two sources winning two fields — and the agent read Data Hub directly, with no API in between.”
Then
Ask “Can we post a new invoice to Thailand?” — it answers no, from the governed trading status, and routes you to the entity owner.
Say
“That is the same Dormant flag from earlier, now stopping a transaction instead of footnoting a board number. One governed attribute, two completely different kinds of decision.”
Second product
Ask “What is outstanding in Indonesia?” — the agent switches to the Open Receivables Lookup tool on its own.
They see
$501,625 open, $387,250 overdue, oldest 80 days — and it volunteers two control issues: an invoice booked in USD when Indonesia reports IDR, and one with no customer name.
Say
“Second data product, different shape, no Data Hub — and it caught the same class of currency error that cost us 26% at the start. One governed definition stops the bad data at the door and explains the number at the board.”
Finish
Ask “Give me a full picture of Thailand” — the agent calls both products and returns one briefing. Then a pronoun follow-up for session memory.
Close
“One definition, one contract, one endpoint — serving a REST client, an agent and this window. The agent was the easy part. The reason you can trust what it said is the golden record.”

If it goes wrong

Stage 2 says “hub: snapshot”

VPN dropped. The page still works on the build-time snapshot — say so plainly rather than pretending. “That chip is telling you it lost the live connection and fell back; the values are the ones we read earlier.” Honesty here reads as confidence.

The agent is slow or times out

First call of a session is slowest — always warm it beforehand. The UI aborts after 5 minutes with a readable message; press Reset and ask again. If Agent Garden is unavailable, stage 4's raw API call still demonstrates the product.

Don't invite derived ratios

The agent has once stated a comparative conclusion its own printed figures contradicted (revenue per employee). Retrieved figures are always correct; the editorial sentence slips. Ask for underlying numbers, not ratios.

If asked about rate limiting or the warehouse

Both are genuinely absent and both are published in /catalog. Say: authentication is enforced, throttling and per-consumer keys are the next step; and the dataset is materialised in the process rather than a warehouse table, with the swap point marked in the code. Volunteering these costs nothing — being caught by them costs the room.

Timing

25 minutes as written. If you have 10, run Act 1 and Act 5 only — the gap and the Thailand moment carry the whole argument. If you have 5, /why alone.
